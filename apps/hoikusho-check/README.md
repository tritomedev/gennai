## 目的

区民の認可保育所の申込みを、1つのEx-Appで2通りに支援する。

| モード | 入口 | できること |
|---|---|---|
| **相談モード** | 自由入力（`message`）＋会話履歴 | 必要書類・記入要領・締切などをAIと会話しながら確認する |
| **チェックモード** | 申込書の画像＋補足フォーム | OCRで読み取り、記入漏れ・不足書類・要件を点検し、利用調整指数の目安を出す |

差し戻し（書類不備で受理不可・利用調整対象外）を減らすのが狙い。認可保育所の入所選考は
区市町村の事務のため、基準は港区の「保育園入園のごあんない（令和8年度版）」に基づく。

## 構成

```
画像（file）／自由テキスト／フォーム選択値
  ↓ 源内プロトコル POST /
【分岐】画像 or チェック用フォームがある → チェックモード／それ以外 → 相談モード

チェックモード
 ① check.extract_from_images() / extract()  … 画像・テキストをLLMで構造化 → JSON
 ② check.apply_form()   … フォームの選択値でLLM抽出結果を上書き（人の明示入力を優先）
 ③ check.run_checks()   … Pythonで決定的に判定（指数計算もPython＝算数ミス防止）
 ④ check.render()       … テンプレ整形（幻覚防止）。冒頭に必ず免責。

相談モード
 chat.chat() … rules.KNOWLEDGE_MD の範囲で回答。範囲外は窓口案内に倒す。
  ↓ {"outputs": Markdown}
```

- `rules.py` … 調査（TASK-037）を機械可読化：事由→必要書類、指数表（代表値）、記入チェック、免責、
  書類同義語辞書、フォームの選択肢定義、相談モード用の制度知識（`KNOWLEDGE_MD` / `CHAT_SYSTEM`）
- `check.py` … 抽出（画像・テキスト）・フォームのマージ・判定・整形のコア
- `chat.py` … 相談モード（会話）
- `llm.py` … Bedrock呼び出しの共通ラッパー
- `main.py` … 源内プロトコル準拠 FastAPI。`GET /schema` が源内Web登録用JSONを返す
- `data/sample_applications.md` … テスト用ダミー申請書（架空）／`data/sample_form.png` … テスト用申込書画像

## 実行

依存（boto3 / fastapi / uvicorn）は `apps/ward-minutes-rag/.venv` を再利用（ベクトルDBは不要）。

```bash
cd apps/hoikusho-check
VENV=../ward-minutes-rag/.venv
$VENV/bin/uvicorn main:app --host 0.0.0.0 --port 8002

# 相談モード
curl -X POST http://127.0.0.1:8002/ -H "Content-Type: application/json" \
  -d '{"inputs":{"message":"就労証明書はいつ発行されたものが必要ですか？"}}'

# チェックモード（フォームのみ。画像は inputs.files に Base64 で入れる）
curl -X POST http://127.0.0.1:8002/ -H "Content-Type: application/json" \
  -d '{"inputs":{"message":"父：会社員 月20日1日8時間。母：パート 月16日5時間。","jukyo":"ku_nai","setai":"kyodai_doen","prepared_docs":"入所申込書,確認書,本人確認書類,マイナンバー確認書類,父の就労証明書"}}'
```

ブラウザ確認用UI（タブで2モードを切替）は `http://127.0.0.1:8002/ui`。

## LLM

- Bedrock `jp.anthropic.claude-haiku-4-5-20251001-v1:0`（クロスリージョン推論プロファイル）。
  **源内バックエンドと同じ Claude 4.5 Haiku が本アプリの認証情報でも利用可能なことを確認**
  （直IDの `anthropic.claude-3-*` はアクセス拒否だが `jp.anthropic.*` プロファイルは有効）。
- 環境変数 `LLM_MODEL` で差し替え可。使えない環境は `amazon.nova-lite-v1:0` に自動フォールバック
  （ただし画像OCRはClaudeのみ）。

## 源内Webへの登録設定（JSON）

`GET /schema` の出力をそのまま源内Webの「リクエスト形式」に貼り付ける（項目定義は `rules.py` から生成）。

```bash
curl -s http://127.0.0.1:8002/schema | python3 -m json.tool
```

| キー | type | 用途 |
|---|---|---|
| `message` | textarea | AIと会話して業務を進める（相談モード）。チェック時は補足として使う |
| `form_images` | file | 申込書・添付書類の画像（最大5枚）→ OCR |
| `jukyo` | select | 住まいと通勤（区内／区外・区内通勤／区外／転入予定） |
| `setai` | checkbox | 世帯の状況（ひとり親・多胎児・きょうだい在園 等7項目） |
| `prepared_docs` | checkbox | 用意した書類（12項目） |
| `conversation_history` | textarea | 源内の疑似チャット（会話を続ける） |

## 動作確認の結果

### 2026-07-24

- `POST /` が HTTP 200／約2秒で2段構え（①不備・要確認 ②指数の目安）を返すことを確認。
- **指数計算はPythonで決定的**（LLMに算数させない）。ひとり親+20・区外通勤−9等を正しく反映。
- 出力冒頭に必ず**免責**（参考・最終確認は窓口・選考は利用調整）を明示。

### 2026-07-30（入力設計の刷新後・ローカル）

| ケース | 結果 |
|---|---|
| 相談モード（就労証明書の発行日） | 締切から3か月以内＋1次/2次の逆算日を回答、末尾に窓口案内と免責 |
| フォームのみ（区外通勤・ひとり親） | 本人確認書類／個人番号／戸籍謄本の不足を検出、調整指数−9を反映、事由が無いため指数は「算出不可」と明示 |
| 画像OCR＋フォーム併用 | 画像から父母の就労状況を読み取り、フォームの「父の就労証明書」と突き合わせて**母の分の不足**を検出 |

- **フォームの選択値はOCR結果を上書きする**。「父の就労証明書」と役割付きで指定された書類については、
  OCR側の役割なしの記述（「就労証明書」）を破棄してから判定する（役割不明＝暫定OK扱いで不足を見逃すため）。
- **修正した既存バグ**：①必要書類の照合が先勝ちで「本人確認書類」「個人番号（マイナンバー）確認書類」が
  `確認書` に誤マッチし、不足を検出できていなかった（最長一致に修正）。
  ②事由が読み取れない入力でも指数を算出・表示していた（算出不可を明示するよう修正）。

## 既知の限界（次の改善）

1. **指数は簡略化した代表値**。基準指数の全テーブル・優先順位13段階は未実装 → 正確化は要一次ソース。
2. **源内側の `file`／`checkbox` の実挙動は未確認**（複数ファイルの可否・サイズ上限・checkboxの返却形式・
   `conversation_history` の実フォーマット）。仕様書に記載がなく実機確認が必要 → TASK-040。
3. 実写真（手書き・傾き・影）でのOCR精度は要検証。読み取り結果は出力の①で利用者に提示して補正させる設計。
4. 相談モードは `rules.KNOWLEDGE_MD` の範囲のみ。記入案・記入例の生成は未実装（TASK-039の残り）。
5. 実データ利用時は**個人情報の扱い**の明文化が必要（POCはダミーのみ）。
