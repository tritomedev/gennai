## ユースケース概要

区民が記入した認可保育所の申込内容を入力すると、**記入漏れ・必要書類の不足・基本要件の該当性**をチェックし、さらに**利用調整指数（点数）の目安**を提示する処理型Ex-App。差し戻し（書類不備で受理不可・利用調整対象外）を減らすのが狙い。

- Ex-Appの1ショット処理に最適（検索ではなく「照合して指摘」）。
- 認可保育所の入所申請・選考は**区市町村の事務**（児童福祉法）。基準は区ごとに異なるため港区で継続。
- 申請書は個人情報を含むため**POCはダミー申請書**。出力は「参考・最終確認は窓口」を明示。

## TASK-037 調査結果（港区・令和8年度＝2026年度）

一次ソースは **「保育園入園のごあんない（令和8年度版）」PDF 全44ページに集約**されている。
URL: https://www.city.minato.tokyo.jp/documents/171277/goannnai08.pdf
（総合案内: https://www.city.minato.tokyo.jp/hoikusien/r8goannnai.html ／ 必要書類: https://www.city.minato.tokyo.jp/hoikusien/sinseisyo08.html ）

### A. 必要書類（事由別）

- **全員共通**：教育・保育給付認定申請書 兼 入所申込書／確認書（父母署名）／本人確認書類／個人番号確認書類。兄弟同時は申込書＋健康状況申告書を人数分。
- **保育を必要とする事由の証明**（父母＋18〜64歳の同居者ごとに1事由）：
  - 就労（従業員/パート/内定）→ 就労証明書（締切から3か月以内発行）
  - 自営・役員・家族従業者 → 就労証明書＋実態書類（確定申告・登記・開業届・営業許可・契約・通帳等）
  - 出産 → 母子手帳（表紙・出産予定日ページ）
  - 疾病 → 診断書（3か月以内・具体記載）／障害 → 手帳（区外在住のみ）
  - 介護看護 → 被介護者の証明＋タイムスケジュール＋実態書類
  - 求職 → ハローワーク受付票／就学 → 就学(予定)証明書（3か月以内）／災害復旧 → り災証明
- **課税・マイナンバー**：住民税は情報連携で区が確認（原則、課税証明の別途提出は不要）。連携不可・未申告時は課税証明or住民税申告。同居の生計中心者がいればその人の分も。
- **該当者のみ（調整・優先に関係）**：ひとり親（戸籍）／低体重児（意見書）／兄が私立幼稚園（給付認定書）／同居18歳未満の手帳／保育士・看護師内定（誓約書＋資格証）／転入予定（契約書＋同意書）等。

### B. 利用調整指数（点数）＝選考基準の核

**世帯合計指数 = 父の基準指数 ＋ 母の基準指数 ＋ 調整指数**。同点は優先順位（13段階）で調整。ひとり親は父母一方の基準指数に **＋20** 後に調整。
根拠: ごあんないPDF p.20-23／[港区保育所入所選考基準適用要領](https://www1.g-reiki.net/city.minato.tokyo/reiki_honbun/g104RG00001975.html)

- **基準指数（抜粋）**：就労 月20日以上×1日8h以上 or 月160h以上＝**20**／6〜8h＝17／4〜6h＝14。就労内定は同条件より低い。月48h以上でも非該当は8。出産＝12／疾病＝入院22・常時病臥20・常時安静14・一般療養11／障害＝1〜2級20・3級14・4級8／介護＝就労テーブル／求職＝2／就学＝就労テーブル／災害＝20。
- **調整指数（17項目・抜粋）**：生活保護+8／両親不存在+8／新規ひとり親+2／申込児or同居児に障害+2／兄弟同園同時申込・在園園へ新規+1／多胎児+1／要介護3〜5の介護+3／保育士・看護師内定+6／**認定を受けてない同居児がいる −1**／**父母以外に保育できる同居親族 −3**／**区外在住×区内通勤 −9**／保育料3か月以上滞納 −20／育休延長も許容 −40（該当時は他調整を不適用）。
- **優先順位（同点時13段階・上位）**：①住民登録・生活の本拠が港区 ②新規入園 ③ひとり親 ④心身障害・疾病 ⑤父母とも就労 …⑫税所得割が低い ⑬港区居住年数。

### C. 記入要領（記入漏れの定番）

- 希望園は**保育園コード**で記入（園名とコード不一致は園名優先）。通いたい順、園数の多寡で有利不利なし。
- **事由は1つしか認定されない**（複数該当でも選択）。就労時間は休憩含めて判断。
- 確認書は各項目チェックし**父母ともに署名**。就労証明書の**発行日が3か月以内**か。
- 申込後に状況が変われば速やかに変更書類（実態相違・虚偽は内定取消し）。

### D. スケジュール・提出（令和8年4月入園）

1次：郵送/電子 10/30〜**11/21必着**、窓口〜12/2。2次：〜**2/9必着**。5月以降は毎月締切。
提出＝窓口・郵送・電子いずれも可（郵送/電子は**必着**）。電子はマイナカード無しだと「2種の電子申請＋郵送」の3点セットが必須。

### E. よくある不備・差し戻し原因（＝チェック項目の宝庫）

- **書類不足は受理不可・利用調整対象外**（繰り返し警告）。
- 就労証明書等の不備で保育の必要性が確認できない → 利用調整対象外。
- 希望園コードと園名の不一致／事由を2つ記入／就労証明の発行日超過。
- 求職→3か月以内に就労証明未提出で退園。区外在住×区内通勤は自動 −9、滞納3か月で −20。

## Ex-App 設計方針（TASK-038）

処理型Ex-App。RAGではなく**ルールベース＋LLM**のハイブリッド。

```
区民の申込内容（テキスト/将来はファイル）
  ↓ 源内プロトコル POST /
  ① LLMで入力を構造化（事由・就労日数/時間・きょうだい・ひとり親・区内外・提出済み書類 等）
  ↓
  ② ルールエンジンで判定（Pythonで決定的に）
     - 事由→必要書類のマッピングで「不足書類」
     - 記入漏れの定番チェック
     - 基準指数＋調整指数で「指数の目安」を計算（LLMに計算させない＝算数ミス防止）
  ↓
  ③ LLMで結果を2段のわかりやすい日本語に整形
     ①不備・要確認（記入漏れ・不足書類・要件該当）
     ②指数の目安と加点のヒント（あくまで参考）
  ↓ {"outputs": Markdown}
```

- **指数計算はルールで決定的に**（LLMの算数を信用しない）。
- 出力冒頭に**「参考です。最終判断・受理可否は港区の窓口でご確認ください」**を必ず明示。
- POCはダミー申請書・テキスト入力。次段でファイルアップロード（源内file機能）→OCR/項目抽出。

## 入力設計の刷新（2026-07-30）

源内Webに登録するリクエスト定義がテキストエリア1個（`application_text`）だったため、
アプリ側が画像を扱えても**源内の画面に画像アップロード欄が出ない**状態だった。
源内が提供するUIコンポーネント（`file` / `select` / `checkbox` / `conversation_history`）を使い、
1つのEx-Appを2モード構成に変更した。

| キー | type | 役割 |
|---|---|---|
| `message` | textarea | AIと会話して業務を進める自由入力（相談モード）。チェック時は補足として使う |
| `form_images` | file | 申込書・添付書類の画像（Base64）→ OCR |
| `jukyo` | select | 住まいと通勤（区内／区外・区内通勤／区外／転入予定） |
| `setai` | checkbox | 世帯の状況（ひとり親・多胎児・きょうだい在園 等） |
| `prepared_docs` | checkbox | 用意した書類 |
| `conversation_history` | textarea | 源内の疑似チャット（会話を続ける） |

- **モード分岐**：画像またはチェック用フォームのいずれかが入力されていればチェックモード、
  それ以外（自由入力のみ）は相談モード。利用者にモードを選ばせない。
- **フォームの選択値はLLM抽出結果を上書きする**。チェックボックスで「父の就労証明書」のように
  役割付きで指定された書類は、OCR側の役割なしの記述（「就労証明書」）を破棄してから判定する。
  役割不明の記述を残すと「どちらの分か不明＝暫定OK」判定になり、不足を見逃すため。
- **読み取り結果を出力の先頭に提示**する。OCRの誤読は避けられない前提で、
  利用者が確認してフォームで補正できるようにした。
- 登録用JSONは実装側の `GET /schema` が返す（定義と実装の二重管理を避ける）。
