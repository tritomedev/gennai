## ユースケース概要

区民が「子どもの補助金について何かないか」と自然言語でチャット入力すると、Ex-App が2段構えで回答する。

1. **AsIs（現行制度）**：区民向けサイトの子育て・補助金ページから現在使える制度を提示
2. **将来的動向**：区議会議事録から「現在議論が進められている」トピックを提示

源内の自作AIアプリ（Ex-App）として実装する。アーキテクチャは蔵書RAGと同型（Ex-App = 源内プロトコル準拠REST API ＋ ベクトルDB ＋ 変換パイプライン）で、データソースが「蔵書」→「区議会議事録＋区民向けサイト」に置き換わる。

### 各区の要点

- **港区**：会議録本文が robots.txt 上は取得可。子育てページは一覧→個別HTMLで素直。公開ラグが3区で最短（約2〜3ヶ月）。注意点は Shift_JIS デコードと、CCBot/Go-http-client等のUAブロック（独自UA設定が必須）。
  - 子育て中核ページ: https://www.city.minato.tokyo.jp/kodomo/kate/teate/
- **中央区**：robots.txt が生成AIクローラ（ClaudeBot/GPTBot/anthropic-ai等）を一律 `Disallow: /`。さらに会議録本文が `.cgi` パスで `/*.cgi` の禁止対象、検索クエリURLも `/*?` で禁止。**robots.txt の観点で3区中もっとも取得に不向き**。
- **江戸川区**：会議録本文は robots.txt 上取得可。子育て補助金ネタが全国屈指に豊富で、デモの回答価値が最も高い。一方で**公開ラグが約5ヶ月と3区で最長**＝「現在議論中」を謳う本ユースケースの中核価値と相性が悪い。
  - 主な子育て支援一覧: https://www.city.edogawa.tokyo.jp/kosodate/kosodate/kosodate_service.html

## 横断的に判明した最重要事項

### 1. 二次利用は3区とも原則「無断転載禁止」

3区いずれも、サイトコンテンツ（議事録・子育てページを含む）の著作権は区に帰属し、**無断転載・改変は禁止**。政府標準利用規約でもCC-BYでもない独自ポリシー。CC-BY相当が適用されるのは各区が明示的に公開する「オープンデータ」のみで、議事録・子育てページは対象外。

→ **RAG化して区民向けに再配布・公開するサービス化には、区の利用許諾が事実上の前提**。一方、社内検証・ローカル閉環境でのPOC・デモに留める限りはリスクは相対的に低い。

### 2. 著作権法40条の論点（要調査・有利に働く可能性）

議会での議員・区長等の発言は「公開して行われた政治上の演説又は陳述」に該当しうる。著作権法第40条第1項は、これらを「いずれの方法によるかを問わず利用することができる」と定めており、**サイト利用規約より上位の法律論として議事録本文の利用余地を広げる可能性がある**。ただし同条には「同一の著作者のものを編集して利用する」ことへの制限があり、RAG（複数発言の抽出・再構成）が適法な範囲に収まるかは要確認。区民向けサイトの制度説明文（区職員の著作物）はこの例外の対象外である点にも注意。

→ TASK-035 として調査タスク化。

### 3. 鮮度は「現在進行中」を名乗れない

議事録は校正・反訳のため会期終了から数ヶ月遅れて公開される（港区2〜3ヶ月／江戸川区5ヶ月）。UI上は「現在議論中」ではなく「直近の議会（◯年第◯回定例会）で議論された」と日付メタデータ付きで正直に表示すべき。

## 区選定の考察

- **中央区は除外候補**：robots.txt がAIボット全面ブロック＋会議録 `.cgi` パス禁止で、技術・規約の両面でもっとも制約が強い。
- **港区 vs 江戸川区のトレードオフ**：
  - 港区＝**鮮度が最良（2〜3ヶ月）**でユースケースの中核価値（議論中動向）と相性が良い。robots.txt も本文許可。Shift_JIS対応が要る程度。
  - 江戸川区＝**子育て補助金ネタが最も豊富でデモ映えは最強**だが、公開ラグ5ヶ月で「議論中」の鮮度が弱い。
- **POCの推奨**：ユースケースの主張（現在議論中の動向提示）を成立させる鮮度を重視し、**第一候補=港区**。デモのインパクト（回答ネタの厚み）を最優先するなら江戸川区。いずれもまずは社内検証・ローカル閉環境のPOCとして進め、公開サービス化の前に利用許諾を検討する。

### 選定結果（2026-07-10 確定）

**港区を採用**。理由は、本ユースケースの中核価値（現在議論中の動向提示）を成立させる公開ラグの短さ（会期後2〜3ヶ月で3区中最良）と、robots.txt が会議録本文ページを許可していること。実装上の留意点は Shift_JIS デコードと、CCBot/Go-http-client 等のUAブロック回避のための独自UA設定。以降の TASK-032〜034 は港区を対象に進める。
