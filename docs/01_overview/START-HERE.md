# Part 1. やさしい概要（非技術者もOK）

## 源内は「AI」じゃなくて「指揮者」

「源内AI」という名前から〈賢いAIそのもの〉を想像しがちだが、実態は違う。源内は
**「どのAIに、どう繋いで、どんな画面で職員に見せるか」を交通整理するだけの"器"**。

- オーケストラでたとえると、源内＝**指揮者**。実際に音を出す（賢い処理をする）のは奏者＝**ExApp**、その声＝**LLM**。
- スマホでたとえると、源内＝**ホーム画面／アプリ管理**。個々のアプリ（ExApp）が仕事をする。

だから源内だけを立てても、それは「賢いAI」ではない。実際に源内の内蔵チャットに
「源内AIって何？」と聞くと **「知りません」と正直に答える**（＝組織固有の知識を誰も与えていないから）。

## 登場人物は3人（三層構造）

```
        ┌─────────────────────────────────────────┐
        │  職員（利用者）                          │
        └───────────────┬─────────────────────────┘
                        │ ログイン・フォーム入力
                        ▼
  ┌──────────────────────────────────────────────────────┐
  │  ① 源内Web（genai-web）＝ 指揮者 / ポータル           │
  │     認証・チーム管理・UI・アプリ登録                  │
  │     ※我々がAWSに構築済み                             │
  └───────┬──────────────────────────────┬───────────────┘
          │ 内蔵チャットは直接             │ ExAppプロトコルで呼ぶ
          ▼                                ▼
  ┌───────────────────┐        ┌───────────────────────────┐
  │ ③ LLM             │        │ ② ExApp（自作AIアプリ）   │
  │  Amazon Bedrock   │        │  組織固有の頭脳            │
  │  Claude / Nova    │        │  例: 社内文書RAG・法令RAG  │
  └───────────────────┘        │  ※クラウド・言語は自由    │
                               │  （その先で自前のLLMを持つ）│
                               └───────────────────────────┘
```

- **① 源内Web**＝入口の器。認証・UI・アプリ管理。**AI能力はゼロ**。
- **② ExApp**＝実際に賢い仕事をする独立サービス。組織のデータに接続するのはここ。**我々が作る／売る対象**。
- **③ LLM（Bedrock）**＝内蔵チャットの頭脳。ExAppは別途自前でLLMを調達する。

> 重要：内蔵チャットのLLM接続と、ExAppのLLMは**共有できない**。ExAppは常に自前でLLMを用意する。

## ここまでで実際にやって分かったこと

- ✅ 源内WebをAWSに**実デプロイ**（東京・稼働中）。デプロイは10〜20分、設定変更の再デプロイは数分。
- ✅ 高額な固定費リソース（NAT Gateway等）を撤廃し、**固定費 月約¥600**まで最小化（POC割り切り）。
- ✅ 自作ExApp（echo-observer）を登録し、**源内が送る実リクエストを丸裸に観察**。
- ✅ 内蔵チャットに質問→Bedrock（Claude）が応答。コストは1チャット **0.3〜1.5円**。

## なぜ我々（システム会社）に商機があるのか

素のLLM（内蔵チャット）は汎用的で賢いが、**その組織固有のこと（社内規程・過去事例・法令の最新条文）は知らない**。
だから価値が出るのは——

> **組織のデータに接続したRAG ExApp** を、
> **データ整備・運用・"判定でなく根拠提示"の設計込みで**提供すること。

RAGのコード自体はコモディティ（誰でも書ける）。本当の商品は、**客の汚いデータを使える形に整える作業・継続運用・信頼の担保**。ここがSIerの飯の種になる。

### 実証：賢いモデルでも法令は間違える（＝RAGが要る証拠）

同じ質問（横断歩道の手前で対向車が停車。一時停止しないと道交法違反か？）を2つのモデルに投げた：

| モデル | 結論 | 引用条文 |
|---|---|---|
| Claude Sonnet 4.6 | 違反の可能性が高い | 道交法**第38条**（正しい） |
| Claude Haiku 4.5 | 一時停止は不要 | 道交法**第36条**（誤り。36条は交差点） |

**同じ状況で正反対の結論**が出て、**片方は条文番号を間違えた**（横断歩道は38条、36条は交差点）。
つまり素のLLMは法令を平気で幻覚する。**本物の条文（e-Gov法令）を食わせるRAGが必須**であり、
かつ **AIに「違反です」と断定させるのは危険**（＝根拠提示の支援ツールにすべき）という結論の生きた証拠。

# Part 2. 技術概要（エンジニア向け）

## アーキテクチャ（正確版）

- **genai-web**（デジタル庁OSS・AWS GenUベース）＝源内Web本体。CloudFront + S3 + Cognito + API Gateway + Lambda + DynamoDB のサーバーレス構成。内蔵チャットは **Amazon Bedrock** を直接呼ぶ。
- **genai-ai-api**（別リポジトリ）＝**ExAppのサンプル実装集**（源内本体ではない）。中身は3テンプレート：
  - AWS: Query Expansion RAG（汎用RAG開発テンプレ）
  - Azure: LLMセルフデプロイテンプレ
  - GCP: **Lawsy**（e-Gov連携の法令RAGアプリ。法令RAGの叩き台になる）
- **ExApp** は源内プロトコルに準拠したREST APIであれば何でもよく、クラウド・言語自由。genai-ai-apiのアプリも自作echo-observerも、立ち位置は同じ「登録される奏者」。

## ExAppプロトコル要点

- `POST` で `{"inputs": {...}}` を受け、`{"outputs": "Markdown可のテキスト"}` を返すだけ。
- **タイムアウト29秒**（`exAppInvokeTimeoutSeconds`）。超える処理は非同期ポーリング。
- 認証は `x-api-key`（登録時のキーがそのまま届く）。
- 実機観察で判明した**仕様書外フィールド**：
  - ヘッダー `x-user-id`（HMACユーザー識別子。PIIを晒さず職員単位の識別が可能）
  - body直下 `sessionId`（会話セッションUUID）
- 詳細: [../02_research/ai-app-api-spec.md](../02_research/ai-app-api-spec.md)

## デプロイ構成（我々の実績）

- リージョン ap-northeast-1（東京）／ アカウント個別 ／ URL: CloudFrontドメイン
- モデル: `amazon.nova-lite` / `jp.anthropic.claude-haiku-4-5` / `jp.anthropic.claude-sonnet-4-6`（東京プロファイル＝データ日本国内）
- **コスト最適化のPOC改変2点**（本番では戻す）：
  1. ExApp呼び出しLambdaのVPC/NAT撤廃 → 固定費 ¥17,000→¥600/月
  2. 新規アカウントのLambdaメモリ512MB制限を、CDK Aspectで全Lambda 512MBキャップして回避
- 詳細: [../04_build/genai-web-deploy-record.md](../04_build/genai-web-deploy-record.md) / [../03_setup/genai-web-aws-cost-breakdown.md](../03_setup/genai-web-aws-cost-breakdown.md)
